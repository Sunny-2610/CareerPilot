# CareerPilot

A job-application agent for college students in India. Upload a resume, get matched
against 500 mock job listings, let the agent draft a tailored resume and cover note,
approve before anything is "sent", track applications and deadlines, and run mock
interviews that remember your weak areas across sessions.

## Run in under 5 minutes

### Prerequisites
- Python 3.11+
- Node.js 18+

### 1. Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate        # Windows (use source .venv/bin/activate on macOS/Linux)
pip install -r requirements.txt
```

Create `.env` in the repo root (copy from `.env.example`):

```
GROQ_API_KEY=gsk_...                  # from https://console.groq.com/keys (primary)
GROQ_MODELS=openai/gpt-oss-120b,openai/gpt-oss-20b,qwen/qwen3.8-27b
OPENROUTER_API_KEY=sk-or-v1-...   # optional fallback, from https://openrouter.ai/keys
DATABASE_URL=                      # leave empty for local SQLite
```

Start the API:

```bash
cd backend
../.venv/Scripts/python -m uvicorn backend.main:app --reload --port 8000
```

The database auto-seeds on first boot: 500 mock jobs, a demo profile
(Ananya Sharma, B.Tech CSE, labelled "Sample data"), and 2 sample applications.
A test resume is at `backend/data/sample_resume.pdf`.

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. The frontend proxies `/api` to port 8000.

## Using a free cloud Postgres (optional)

The app runs offline on SQLite (`backend/careerpilot.db`) with no configuration.
To use Postgres:

1. Create a free database at [Neon](https://neon.tech) or [Supabase](https://supabase.com).
2. Copy the connection string and append `?sslmode=require`, e.g.
   `postgresql://user:password@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require`
3. Put it in `DATABASE_URL` in `.env`.
4. Restart the backend; tables are created automatically.

Reset the database (works on SQLite and Postgres):

```bash
python -m backend.data.reset    # drop all tables, recreate, reseed
```

Regenerate the 500 mock listings (fixed seed, repeatable):

```bash
python -m backend.data.generate_jobs
```

## How the agent works

- Backend runs a LangGraph orchestrator (`backend/agent/graph.py`): it recalls memory,
  tailors the resume, generates the PDF, creates the application in
  `awaiting_approval`, and writes a calendar reminder — max 8 steps, every step logged
  to the action log and shown in the UI.
- The agent **cannot** set an application to "applied". Only the
  `POST /api/applications/{id}/approve` button can.
- Tailored output is validated in code against the profile: invented skills, projects
  or employers are dropped and logged.
- If every provider/model in the fallback chain fails (Groq models first, then
  OpenRouter models) or all keys are missing, the app falls back to deterministic
  code paths (heuristic resume parsing, code-computed fit bullets, fallback interview
  questions with heuristic scoring) and stays usable.

## Key endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/profile/upload` | Upload PDF resume, parse into profile |
| GET | `/api/jobs?q=&role=&location=&type=&closing_soon=&page=` | Jobs, server-side pagination (25/page) |
| GET | `/api/jobs/{id}` | Job detail with LLM "why it fits" bullets |
| POST | `/api/applications/prepare` | Run the agent for a job |
| POST | `/api/applications/{id}/approve` | The only way to reach "applied" |
| GET | `/api/today` | Attention items, weekly counts, deadlines |
| POST | `/api/practice/start` | Start mock interview |
| POST | `/api/practice/answer` | Evaluate answer, update weak areas |
| GET | `/api/practice/memory` | Weak areas across sessions |
| GET | `/api/log` | Action log |
| GET | `/api/health` | App + database status |

## Deploying (Render + Vercel, free tiers)

The backend deploys to Render and the frontend to Vercel; Vercel proxies `/api/*`
to Render so the browser sees a single origin.

1. **Render (backend API)** — New Web Service from this repo:
   - Build: `pip install -r backend/requirements.txt`
   - Start: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`
   - Env vars: `DATABASE_URL` (Neon), `GROQ_API_KEY`, `OPENROUTER_API_KEY`,
     `CORS_ORIGINS` (your Vercel URL)
   - Health check: `https://<render-app>/api/health`
   - A `render.yaml` blueprint is included.
2. **Vercel (frontend)** — import the repo with **Root Directory: `frontend`**.
   Then put your Render URL into `frontend/vercel.json` (replace the
   `REPLACE-WITH-YOUR-RENDER-APP` placeholder) and push — Vercel redeploys
   automatically.
3. Never commit `.env`; set all secrets in each platform's dashboard.

## Notes

- All jobs and companies are **fictional mock data** generated by a seeded script.
- Reminders are `.ics` files in `backend/outputs/` — no Google OAuth.
- Never commit `.env` or real keys.
